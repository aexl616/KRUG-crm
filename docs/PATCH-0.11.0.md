# 0.11.0 — График сотрудников и выбор специалиста

Клиенту предлагается работающий специалист после выбора услуги, даты, времени и длительности. Ручной выбор другого сотрудника и «Любой доступный» сохраняется при обновлении формы. Если ручной выбор стал недоступен, форма просит выбрать заново, не подменяя человека.

## Сервер

- `services.staff_selection`: `none`, `optional`, `required`. Для записи, записи со сведением и услуг работы на студии включён `optional`; аренда остаётся `none`.
- Профиль связан с серверным сотрудником CRM: имя/ник, HTTPS-фото, год начала работы, жанры, описание, публикация и порядок предложения. Квалификация задаётся списком услуг.
- `schedule.weekly`: ключи `1`–`7` (ПН–ВС), массивы `{start,end}`. До 8 интервалов в день; отсутствующий день или пустой массив — выходной. Конец раньше начала означает следующую дату; равные часы запрещены. Пересекающиеся интервалы объединяются при проверке покрытия.
- `schedule.exceptions`: даты `YYYY-MM-DD` с такими же массивами. Исключение заменяет весь календарный день, включая переходящий интервал предыдущего дня. Отпуск сохраняется набором пустых дат. Все вычисления в `Europe/Moscow`.
- Доступность требует покрытия всей сессии, активного опубликованного сотрудника, квалификации, отсутствия бронирований и технических блоков. Занятость единственной комнаты учитывается из `bookings` и общего серверного состояния CRM, без повторного учёта копий Mini App.
- Стабильный приоритет: `priority`, затем `staff_id`. API возвращает публичные карточки и `defaultStaffId` для каждого слота; причины отпуска, логины и закрытые данные не публикуются.
- Создание через `krug_create_booking_v4` атомарно выбирает/проверяет сотрудника под блокировкой комнаты, вызывает существующую запись/бонусы и сохраняет назначение. «Любой доступный» передаётся как `null`, сервер назначает подходящего. `required` отвергает отсутствие конкретного выбора.
- Повторный request ID возвращает прежнее назначение и проверяет Telegram-владельца. История и CRM получают `staffId`/`staffName` с сохранённым именем. Старые серверные RPC создания закрыты для прямого вызова через service role.
- Сохранение графика доступно owner/admin через сессию CRM; версия защищает от перезаписи параллельных правок. Новые таблицы имеют RLS, закрытые функции не доступны anon/authenticated.

## Интерфейсы

- CRM: кнопка «График работы» в карточке сотрудника; диалог с недельными интервалами, исключениями/отпуском и публичным профилем/услугами.
- Mini App (`apps/miniapp`): карточки специалистов на шаге времени и подтверждения. Бейдж «Сегодня работает» вычисляется по московской дате, иначе — «В этот день работает». Назначенный человек показан в результате заявки.
- Обработаны загрузка, повтор после ошибки, отсутствие кандидатов, недоступность ручного выбора и конфликт при отправке. Для `none` блок скрыт; для `required` нет «Любой доступный».
- Если CRM пытается сохранить комнату, которую заняли через Mini App, сервер отклоняет запись, CRM восстанавливает серверное состояние и показывает причину.

## Проверка

- 55 тестов API и Mini App, плюс существующие пять тестовых файлов CRM (финансы, данные, почасовые расчёты, уведомления, настройки).
- SQL: вся последовательность миграций выполняется в PGlite, затем проверяются ночные смены, перерывы, исключения, квалификация, приоритет, назначение, повторные запросы, обязательность, общая комната, права и RLS. Проверен вызов v4 от service role. Это локальный SQL-тест, не тест боевой базы и не нагрузочная проверка параллельных соединений. Недоступный в WASM pgcrypto заменён только тестовыми заглушками для старых auth-fixtures; криптография не тестируется.
- Браузер Mini App: 390/900 px, ручной выбор и смена времени, «Любой доступный», отправка, серверная цена, история, отмена, ошибка авторизации и повтор.
- Браузер CRM: 390/1100 px, недельный/ночной интервал, отпуск, сохранение с версией и отмена. Внешние записи в браузерных тестах замоканы. Экраны проверены визуально, горизонтального переполнения нет.
- CI дополнен SQL-проверкой, проверкой нового CRM-скрипта и запуском для PR.

## Выпуск

Применить миграцию `20260912120216_staff_schedule_selection.sql` вместе с новым API/Mini App в согласованном выпуске. До открытия записи заполнить и опубликовать реальные профили, квалификации и графики через CRM. Пустой график означает недоступность: патч не выдумывает рабочие дни существующих сотрудников. Миграция сразу включает optional у студийных услуг, поэтому до настройки графиков их слоты закрыты.

В этой работе боевые миграции и деплой не выполнялись. Режим выбора услуги меняется серверным полем; отдельный редактор этого режима и циклические шаблоны 2/2 не входят в патч. Старые локальные черновики в отдельной папке `mini-app/` не изменены. Финансовые функции и исторические записи не удалялись.

Основные файлы: миграция и `supabase/tests/`, `api/{availability,bookings,services,crm-auth,crm-state}.js`, `api/tests/`, `crm-staff-schedule.js`, `crm-miniapp-sync.js`, `crm-cloud-sync.js`, `app.js`, `index.html`, `apps/miniapp/{app,booking,data,styles}.*`, браузерные/модульные тесты, `.github/workflows/tests.yml`.
