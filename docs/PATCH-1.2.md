# Patch 1.2 — Data Layer Preparation

Продолжен 10 сентября 2026 из checkpoint 0ecf35e поверх текущих почасовых услуг, Settings 2.0 и интерфейса. Реализация локальная; отдельный релизный коммит пока не создан, поскольку предыдущие настройки и UX также не закоммичены.

## Решение

`data-store.js` содержит синхронный DataStore и заменяемый LocalStorageAdapter. Бизнес-код сохраняет глобальный state, но не обращается напрямую к браузерному хранилищу. Ключ studio-income-app-v1 сохранён. Нового backend, сети, зависимостей и продуктового UI нет; добавлено только сообщение об ошибке сохранения.

API: loadState/saveState, readState для безопасного слияния метаданных, getCollection/setCollection, createEntity/updateEntity/deleteEntity, reloadState. Коллекции могут включать массивы сущностей и объекты настроек. Entity helpers не заменяют бизнес-проверки ролей и уведомления.

## Миграция и безопасность

Миграции по-прежнему выполняют normalizeState, KrugHourly, KrugSettings, KrugFinance и нормализация уведомлений. Старые и неизвестные поля сохраняются. Миграция каталога использует переданный каталог, а не состояние прежней загрузки. Версия формата не менялась.

Сериализация работает с копией. Некорректные корневые значения, циклы и неподдерживаемые значения отклоняются. Undefined-поля объекта не записываются; undefined в массиве отклоняется. Ошибка чтения/миграции блокирует перезапись до успешного восстановления чтением и нормализацией. Повреждённые данные не очищаются автоматически. Ошибки логируются без содержимого state.

При неудаче сохранения расходов, плана или правил настроек возвращается ошибка, изменения этих операций откатываются в памяти. Прочие прежние сценарии могут сохранять изменения только в памяти — общий баннер явно предупреждает не закрывать вкладку. Системные уведомления не отправляются при неудачной записи.

## Несколько вкладок

Существующие Web Locks напоминаний сохранены. Обновление прочтения/напоминаний читает свежие данные и не заменяет их устаревшими записями. Есть opt-in reloadState; автоматическая перезагрузка открытых форм не добавлялась. Одновременные полные бизнес-сохранения остаются last-writer-wins, как прежде: это не облачная синхронизация.

## Изменённые файлы этого этапа

data-store.js, app.js, finance.js, notifications.js, settings-ui.js, index.html; тесты data-store/finance/settings/hourly/notifications; этот отчёт и ROADMAP. Удалены прямые обращения хранения из app.js и notifications.js. В бизнес-коде их осталось 0; физические getItem/setItem — два вызова внутри адаптера. removeItem не используется.

## Проверки

166 автоматических проверок: 24 data layer, 42 finance, 26 settings, 46 hourly, 28 notifications. Среди них: старые данные и неизвестные поля, битый JSON, отказ записи, CRUD, независимые копии, подмена адаптера, чтение другой вкладки, защита метаданных, почасовые снимки и настройки после reload, повтор сохранения расхода без дубля.

В отдельном Edge на тестовых данных: вход, создание расхода 123,45 и reload; создание завершённой записи через кнопку, одна связанная оплата 1200 после reload; мобильный экран 390×844 без горизонтального переполнения и ошибок JavaScript. Визуально просмотрен мобильный экран, десктопные действия выполнены при 1440×1000. Полный ручной цикл редактирования/удаления всех сущностей не повторялся; соответствующие имеющиеся автоматические проверки прошли.
